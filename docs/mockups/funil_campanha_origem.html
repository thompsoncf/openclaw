2 · de onde vem o dado

Já existe — é o mesmo dado que a aba Base já mostra

A aba Base já junta campanha_alvos + campanhas pra saber por qual campanha um contato passou (usa o contato mais recente, com order by ultima_msg_em desc, id desc limit 1). A mudança é levar essa mesma consulta pra query do Funil — hoje ela nem participa dessa junção.

4 · de onde vem o apelido do chip

Mesma junção que já existe no Inbox — não é dado novo

Quem entrou pelo WhatsApp já carrega isso: conversas.chip_id aponta pra qual número recebeu, e o apelido vem de contas.nome (chip secundário) ou de canais_config.rotulo (chip principal, quando chip_id é nulo) — o mesmo coalesce que a lista de Conversas já usa pra rotular a linha "veio pelo Chip X". Pra chegar no card do Funil, junto pela conversa de WhatsApp ligada ao lead.

6 · resumo

O que muda no código (depois de aprovado)

  • Query do /painel/prospeccao (kanban) ganha o mesmo left join lateral em campanha_alvos+campanhas que a aba Base já usa — sem tabela nova, sem migração.
  • Junta também a conversa de WhatsApp do lead pra pegar chip_id → contas.nome/canais_config.rotulo, igual ao Inbox — e só mostra o sufixo "· 📱 apelido" quando _tem_dois_chips() for verdadeiro e o apelido não vier vazio.
  • O card ganha uma linha .camp-pill (opção B), só quando o lead tem campanha associada — sem alterar os outros elementos do card.
  • Reaproveita min-width:0/overflow:hidden/text-overflow:ellipsis do conserto da PR #541 pra truncar nome de campanha (e chip) grande, com o mesmo cuidado.
  • Teste de regressão novo garantindo que o selo só aparece com dado, que o sufixo do chip só aparece com 2+ chips, e que a cor bate com o tema (mesmo padrão dos testes de inspeção de fonte já existentes no arquivo).
Aguardando aprovação final: o selo (opção B) + o apelido do chip como mostrado na seção 4 está bom pra eu implementar de verdade?
